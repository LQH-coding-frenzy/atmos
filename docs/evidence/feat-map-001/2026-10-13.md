# FEAT-MAP-001 — RainViewer radar overlay

**Date:** 2026-10-13

**Status:** Implementation complete; protected production release pending

**Runtime:** Cloudflare Gateway metadata contract + Vercel/MapLibre tile rendering

**Production deployment:** Not yet performed; owner authorized continuing after configuring the Worker secret

## Implementation

- Added `GET /api/v1/weather/radar/frames` to the gateway. It validates the RainViewer response, accepts only the documented tile host and frame path shape, limits metadata to 64 KB, uses a five-second upstream timeout, and caches normalized metadata for five minutes.
- Added the application-owned `weatherRadarTimelineSchema`; browser UI does not read RainViewer's raw metadata response.
- Added a selectable RainViewer raster overlay with frame slider, previous/next controls, manual play/pause, opacity control, and RainViewer attribution. Playback is user-started and advances every 15 seconds to moderate tile requests; the map continues to support city previews.
- Limited rendered tile zoom to 7, matching RainViewer's current free API cap. The CSP allows only the required RainViewer tile host.
- Added optional OpenWeather Weather Maps 1.0 layers for precipitation, clouds, pressure, wind, and temperature. The gateway reports whether `OPENWEATHER_API_KEY` is configured, allowlists tile layers/coordinates, rate-limits cache misses per Worker isolate, caches images for five minutes, and never returns or logs the key. OpenWeather overlays are current snapshots and are not animated.
- Updated map-provider provenance and the existing FEAT-MAP-001 task record. No database change or paid resource was added. The owner reports that the production Worker secret is configured; its name/value was not inspected or logged in this work.

## Provider constraints

RainViewer's free API is described as for personal and educational use and currently provides past radar frames only (up to two hours, 10-minute steps). Free nowcast/forecast frames are not used. The integration is best-effort and not suitable for safety-critical decisions.

OpenWeather's free Weather Maps 1.0 current layers require an API key. The app's provider-key policy keeps provider keys server-side; the owner reports `OPENWEATHER_API_KEY` is configured in the production Worker secret store, and the UI enables those layers only when the deployed gateway reports it. OpenWeather history/forecast radar maps are paid and excluded. The per-isolate guard is best-effort and does not enforce the provider's aggregate monthly quota across Cloudflare locations. The owner authorized continuing with the protected activation flow on 2026-10-13.
