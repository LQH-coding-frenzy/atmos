# HIST-CAP-001 — User-captured weather history

## Outcome

- Added a signed-in-only history view for the current selected coordinates with 7-, 30-, and 90-day windows.
- Users explicitly record the currently displayed Open-Meteo observation; no background collection, provider backfill, or new provider request was introduced.
- Reads and writes pass through the existing authenticated Worker-to-Supabase Edge Function route. The API validates coordinates, timestamps, and normalized observation fields, derives `user_id` from the verified JWT, uses the existing `weather_snapshots` RLS table, and returns private no-store responses.
- Snapshot writes accept only current observations no older than 24 hours and reject timestamps more than five minutes in the future, preventing the manual capture endpoint from becoming a historical backfill path.
- History is bounded to 100 rows per request. No migration, schema, RLS, provider, or infrastructure change was made.
