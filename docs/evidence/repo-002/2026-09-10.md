# REPO-002 Branch Protection Remediation Evidence

- `main` already requires pull requests, strict status checks, admin enforcement, stale-review dismissal, and conversation resolution.
- The audit found force pushes enabled despite the master-plan prohibition.
- This remediation disables force pushes without changing required checks or weakening any existing protection.
- CODEOWNERS exists, but review enforcement remains deferred because only one repository owner is known and self-approval is prohibited; enabling it now would deadlock protected changes.
- No application, workflow, database, infrastructure, or production runtime changes.
- GitHub's protection API now reports `allow_force_pushes.enabled: false` while preserving all eight strict required contexts and existing admin/review/conversation rules.
- The configured security-reviewer was unavailable because its model could not be resolved; manual comparison found no changed rule other than force-push prohibition.
