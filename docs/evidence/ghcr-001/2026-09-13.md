## Protected Implementation

- PR #141 introduced the release workflow and bootstrap image. Pull requests receive only `contents: read` and run the build/label validation job; the protected-main publish job alone receives `packages: write`.
- Every action is pinned to a full commit SHA, checkout credentials are not persisted, publishing requires `refs/heads/main`, and concurrent publications on one ref are serialized.
- The only image tag is `sha-<full-git-sha>`. Metadata explicitly disables `latest`, and publication fails before build/push if the exact tag already exists.
- The first PR security run `34767666886` correctly failed Trivy rule `DS-0002` because the initial `scratch` bootstrap omitted a non-root `USER`. Commit `f155218` added numeric user `65532:65532`, matching file ownership, and regression coverage. The next Trivy run passed without suppression.
- Updated PR #141 passed container validation, quality, database, Playwright, CodeQL, Gitleaks, Semgrep, Trivy, SBOM, and Vercel checks before merging as `10633f1`.
- The first protected publication run `34768012927` successfully created the repository-linked package and digest `sha256:f52ae381748398c9d7dedd9e00fefad7d9c5174bef416fa436c1df9f2438a01b` from exact merge SHA `10633f1d97a5098e8c19cd4da9db4ae12dd2501c`.
- That run exposed Node 20 deprecation warnings from the initially pinned action majors. PR #142 moved only the new container workflow to upstream action majors whose manifests declare `node24`, preserving full-SHA pins and permissions. All protected checks passed before merge as `509214a`.
- Local validation passed four GHCR policy tests, all 56 Vitest and 40 Node tests, lint, typecheck, scoped formatting, `git diff --check`, and two bootstrap Docker builds. `actionlint` and local Trivy were unavailable; protected workflow parsing and Trivy supplied those gates.
