# ALERT-INAPP-001 — In-app weather alert rules

## Outcome

- Signed-in users can create, pause, and delete in-app-only threshold rules for temperature, rain probability, wind, or thunderstorm conditions.
- The dashboard evaluates rules against current weather and the next-hour forecast while users view it. It respects enabled state and configured weekdays; unsupported legacy conditions are marked unsupported rather than reported as healthy.
- Rule CRUD uses the authenticated Supabase Edge API and existing caller-owned RLS policies. No alert events are written.
- No migration, RLS policy change, queue, cron, notification service, paid resource, or external alert vendor was added.
- Email/push delivery and background alert evaluation remain deferred.

## Rollback

Revert the API routes, in-app panel, and domain evaluator. Existing alert rules remain user-owned under RLS; no event or notification-delivery state is created.

## Production configuration

- The first live render reported account access unavailable because the deployed bundle lacked the Supabase project URL.
- The owner added the existing public Supabase URL and publishable key to Vercel Production. The protected Vercel rebuild now renders the email/password sign-in form in Saved places and the signed-out prompt in Alerts, confirming browser-client initialization without exposing either value.
- Anonymous alert GET, POST, PATCH, and DELETE requests all return 401. No Auth user, alert rule, or external-delivery resource was created during verification.
