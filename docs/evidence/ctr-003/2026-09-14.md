# CTR-003 Evidence

## Scope And Gate

- Exact dependency `CTR-002` was `DONE` before implementation. CTR-003 added only a reusable GitHub Actions verification workflow, its static policy test, documentation, and task record. It created no Azure resource, database change, secret, signing key, package publication, or paid resource.
- `Verify container supply chain` accepts one input: a strict `sha256:<64 lowercase hex>` digest for the fixed public package `ghcr.io/lqh-coding-frenzy/atmos-jobs`. It rejects all tag or image-name caller input before any remote fetch.
- The workflow has only `contents: read`. It does not mint an OIDC token, authenticate to GHCR, publish, sign, attest, deploy, or use a secret. Its sole third-party action is the full-SHA-pinned Cosign installer at v4.1.2, which installs Cosign v3.0.6.

## Verification Contract

- The gate anonymously pulls `image@sha256:<digest>`, requires OCI source `https://github.com/LQH-coding-frenzy/atmos`, and requires a full lowercase 40-character OCI revision.
- It verifies the exact digest signature and CycloneDX attestation independently against GitHub OIDC issuer `https://token.actions.githubusercontent.com`, repository `LQH-coding-frenzy/atmos`, ref `refs/heads/main`, and certificate identity `https://github.com/LQH-coding-frenzy/atmos/.github/workflows/release-containers.yml@refs/heads/main`.
- Both Cosign commands additionally require the GitHub signing workflow SHA to equal the OCI image revision. Transparency-log verification remains enabled by default; no insecure, key, regular-expression identity, or bypass flag is configured.
- A future Azure workflow must invoke this reusable workflow and make deployment depend on its success. Verification failure is a release stop. No Azure deployment exists or was attempted by CTR-003.
