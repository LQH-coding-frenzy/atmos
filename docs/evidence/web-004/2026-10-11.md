Status: `DONE` in the local, uncommitted `feat/weather-dashboard-upgrade` worktree. No deployment or database schema/policy change was performed.

## Scope delivered

- Signed-in users can rename a saved place inline. The API validates the UUID/name, filters by both row ID and authenticated user ID, and uses the existing owner-only RLS `UPDATE` policy.
- The saved-location RLS test now verifies owner rename and delete while preserving cross-user update isolation.
- The sign-in panel offers password recovery via the existing Supabase Auth client. It sends a same-origin redirect to `/auth/update-password` and returns a non-enumerating confirmation message.
- The recovery route accepts a valid Supabase recovery session, enforces matching 8–128-character passwords before calling Supabase Auth, and presents a safe expired-link state without a session.
- No password, email address, access token, or recovery credential is written to application logs.
