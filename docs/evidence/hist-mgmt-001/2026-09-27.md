# HIST-MGMT-001 — Delete own history observations

## Outcome

- Added an accessible, per-observation delete control in the signed-in history panel.
- Added an authenticated Edge API DELETE route. It validates the snapshot UUID, uses the caller-scoped Supabase client, and returns a generic 404 for absent or non-owned rows. Existing RLS remains the ownership boundary.
- Added DELETE to Worker and Edge Function CORS allowlists. No schema, grants, RLS policy, or stored-data shape changed.
- Deletes are permanent and limited to the single observation the user selects; there is no delete-all operation.
