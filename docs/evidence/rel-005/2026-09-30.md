# REL-005 Progress Evidence

Status: `IN_PROGRESS`. Source-side affinity is ready; the Cloudflare Transform Rule and version-split verification remain pending.

## Scope and dependencies

- The owner reopened REL-005 and authorized the production API-origin and Cloudflare request-header Transform Rule changes on 2026-09-30.
- Canonical dependency `REL-004` is `DONE`; infrastructure foundations `TF-001` and `TF-002` are also `DONE`.
- The custom API hostname `api.rainify.dpdns.org` is already provisioned and live. Existing evidence records successful `/health` and `/version` probes.
- A read-only Cloudflare API query found no `http_request_late_transform` entrypoint for the zone. No Cloudflare resource was changed during preflight.
- The first HCP speculative plan proposed one ruleset creation and no destroys, but warned that the Rules Language `matches` operator requires a paid Business/WAF Advanced plan. The rule was revised to check only for a non-empty header; the client itself generates UUIDv4 values.
- A subsequent HCP Terraform apply for the Free-compatible expression created only `cloudflare_ruleset.worker_version_affinity`; a follow-up plan reported no changes.

## Implementation

- Production Vercel API calls use the existing custom API hostname; `workers.dev` remains the local/CI fallback.
- Browser clients generate a random UUIDv4 in tab-scoped `sessionStorage` and send it in `X-Atmos-Version-Key`. The key is routing state only, not authentication or a user identifier.
- Worker CORS permits the header only for the configured frontend origin. The Worker does not log or forward the affinity key.
- The production Terraform root defines a zone `http_request_late_transform` rule for `api.rainify.dpdns.org` that maps a non-empty session key to `Cloudflare-Workers-Version-Key`.
- ADR 0003 records the session-storage header choice and rollback behavior.
- Protected Edge release [36842612367](https://github.com/LQH-coding-frenzy/atmos/actions/runs/36842612367) deployed Worker CORS support. A read-only custom-host CORS preflight returned HTTP `204` and allowed `X-Atmos-Version-Key`.
