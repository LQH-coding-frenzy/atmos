# GAME-001 Evidence

- Fresh normalized weather remains cached for five minutes under the public request key.
- A separate internal cache key retains a stale-marked normalized response for at most one hour.
- Provider failure returns the stale response with `x-cache: STALE`, `meta.cached: true`, `meta.stale: true`, and `private, no-store` to prevent client re-caching.
- Provider failure without a stale entry retains the typed sanitized `WEATHER_UNAVAILABLE` response.
- Open-Meteo requests abort after five seconds and are not automatically retried.
- Cached objects contain no per-request request ID, trace context, token, cookie, or user data.
- User-supplied reserved cache parameters are removed from the fresh key, and cache read/write failures do not suppress valid live weather.
- No remote deployment, provider change, durable state, or paid capability is included.
- Twenty-one focused provider/gateway tests, root typecheck/lint, Worker dry-run bundle, formatting, and diff checks passed.
- The configured reviewer was unavailable because its model could not be resolved; manual review found no stale-window, key-collision, cache-leakage, or failure-classification issue.
