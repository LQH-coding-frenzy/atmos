Status: `DONE` in the local `feat/weather-dashboard-upgrade` worktree; no deployment or persistent data change was made.

## Behavior

- Users open **Compare cities**, search with the existing location-search gateway, and explicitly choose a second city.
- The comparison weather request goes through the existing validated, cached Atmos gateway. It is not issued until a city is selected. Previous requests are aborted or ignored when another choice/search replaces them.
- The panel compares current temperature, condition, humidity, wind, and next-hour rain chance, with observed/stale metadata for both cities.
- A temperature delta is shown in the selected unit. Fahrenheit differences use only the 9/5 scale conversion, without a +32 offset.
- The main location and share URL remain unchanged until the user activates **Make <city> current**. Switching then uses the existing location-selection path and URL handling.
- Search, no-results, weather-load, duplicate-current-city, stale-data, and switch-failure states remain explicit; closing a comparison aborts pending work.
