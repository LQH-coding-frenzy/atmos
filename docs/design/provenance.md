# Design Provenance

The Skyglass/Observatory redesign follows the owner-selected dual composition documented in [the UI design contract](skyglass-ui.md). Its CSS, typography hierarchy, tonal surfaces, and browser glass treatments are original implementation informed by public Material 3 and Apple materials guidance. Base-vector map colors adapt to the selected theme; radar rasters and weather-marker colors retain their data meaning.

The user-provided dashboard image and rough Vite design are visual references only. Their bundled avatar and map image are not shipped by the Atmos application.

The production dashboard uses original CSS and Lucide icons. Its MapLibre Weather Watch map loads the OpenFreeMap Liberty public style (`https://tiles.openfreemap.org/styles/liberty`), with vector tiles derived from OpenStreetMap. OpenFreeMap's public service is free, requires no registration/API key, allows commercial use, and is provided as-is without an availability SLA. The owner approved its use on 2026-10-11. MapLibre's attribution control displays OpenFreeMap, OpenMapTiles, and OpenStreetMap attribution.

Weather Watch's optional radar layer uses RainViewer's public Weather Maps API. The gateway validates and normalizes frame metadata; MapLibre requests radar tiles from `https://tilecache.rainviewer.com`, and its attribution control identifies RainViewer. The free API currently exposes only past radar frames (up to two hours, 10-minute intervals), limits tile zoom to 7 and usage to 100 requests per IP per minute, and is described by RainViewer as for personal and educational use. It has no free forecast/nowcast frames or availability guarantee; do not describe the overlay as a forecast or depend on it for safety-critical decisions. Source: [RainViewer API transition summary](https://www.rainviewer.com/api/transition-faq.html) and [Weather Maps API](https://www.rainviewer.com/api/weather-maps-api.html). The owner selected this limited free integration on 2026-10-13.

The map also supports optional OpenWeather Weather Maps 1.0 current layers (precipitation, clouds, pressure, wind, and temperature). Browser tiles pass through the Atmos gateway; the OpenWeather API key is a server-side `OPENWEATHER_API_KEY` Worker secret and is never returned to the browser. The layer selector remains disabled unless the gateway reports the key configured. These free layers are current snapshots, not animated radar/history/forecast data. The quantitative color keys use OpenWeather's published [Weather Maps 1.0](https://openweathermap.org/api/weathermaps) [legend stops](https://openweathermap.org/map_legend); pressure stops are documented in Pa and displayed in hPa, while temperature/wind thresholds follow the selected display units. Source: [OpenWeather pricing](https://openweathermap.org/price). No key has been created or configured in this task.

The optional Air quality map layer samples the existing Open-Meteo Air Quality gateway route only after selection, for the current place plus at most seven saved places in the visible map bounds. Samples are model estimates derived from CAMS, labeled with observation time/cache status, capped at eight locations per view, two concurrent requests and twelve new map requests per minute per open map session, and cached in memory for five minutes. The map draws discrete point markers only; it does not interpolate or imply monitor coverage between them. A missing U.S. or European AQI stays unavailable, never zero. Model resolution varies (~11–45 km); these points are not ground-station readings. Sources and attribution: [Open-Meteo Air Quality API](https://open-meteo.com/en/docs/air-quality-api) and [Copernicus Atmosphere Monitoring Service](https://atmosphere.copernicus.eu/).

The activity planner is a deterministic suitability estimate over the currently selected hourly forecast. Its optional AQI input is loaded only when the user requests it, through the existing Open-Meteo/CAMS timeline route. Missing dimensions reduce displayed input coverage and pull scores toward neutral; no missing value is interpreted as favorable weather. Custom activity thresholds remain in component state for the current page session and are not account-synced. Planner scores are not health, safety, or travel advice.

The on-demand official warning center sends a same-origin POST with the selected location in its request body to an existing Next.js server route; coordinates are not placed in a browser-visible query string. The server queries the U.S. National Weather Service (NWS) only for locations whose geocoding country is the United States, then confirms a supported NWS forecast grid through its official `/points` API before querying active alerts. A point outside an NWS grid is returned as unsupported, not as an empty alert result. Environment and Climate Change Canada (ECCC) is queried only for Canadian locations. Unsupported or unidentified countries return an explicit unsupported-coverage response without calling either warning provider; this is distinct from a supported source returning no active alerts. Source fields, alert text, times, and impacted areas are reproduced without rewriting, and links point only to official NWS/ECCC endpoints. NWS requests include the required identifying User-Agent. Next.js server-side fetch caching and a bounded 60-second in-instance cache reduce upstream refreshes; there is no database or durable user-location storage. ECCC alert data is attributed to Environment and Climate Change Canada under its August 2026 v2.1.1 end-use licence; some marine products may be incomplete. NWS also documents service gaps for some marine alerts and SPC SEL tornado-watch language. WMO SWIC reports wider participating-member CAP warnings, but its documentation notes inaccessible/incomplete feeds and marine gaps and does not establish a stable application API, so it remains excluded. The warning center is informational, not an emergency-alert service; follow local authorities and official sources. Source integration was approved on 2026-10-19. Production release remains separately gated.
